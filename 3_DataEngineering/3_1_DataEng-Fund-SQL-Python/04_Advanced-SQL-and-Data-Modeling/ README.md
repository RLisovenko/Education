- Calculates the revenue generated by each order
- by multiplying the ordered quantity by the unit price.
- quantity * unit_price - price of Order
```
SELECT
    order_id,
    product,
    quantity,
    unit_price,
    quantity * unit_price AS revenue
FROM orders;
```
- Calculates total customer spending by joining customers with their orders,
- summing the revenue from all orders, and ranking customers by total spend.

```
SELECT
    c.customer_name,
    SUM(o.quantity * o.unit_price) AS total_spend
FROM customers c
INNER JOIN orders o
ON c.customer_id = o.customer_id
GROUP BY c.customer_name
ORDER BY total_spend DESC;
```

- Calculates order statistics for each customer, including the total number of orders
- and the average order value, while also keeping customers without orders.
```
SELECT
    c.customer_name,
    COUNT(o.order_id) AS total_orders,
    AVG(o.quantity * o.unit_price) AS average_order_value
FROM customers c
LEFT JOIN orders o
ON c.customer_id = o.customer_id
GROUP BY c.customer_name
ORDER BY total_orders DESC;

```

## Common Table Expressions (CTEs)

CTEs are temporary named query results created with `WITH`.
They make complex SQL queries easier to read, structure, and reuse.

- Adds the remaining sample orders (`106–108`) to the existing `orders` table.
- `ON CONFLICT` prevents duplicate `order_id` errors if the records already exist.

```sql
INSERT INTO orders
(order_id, customer_id, product, quantity, unit_price, order_date)
VALUES
(106, 2, 'Keyboard', 1, 1600.00, '2026-08-05'),
(107, 1, 'Laptop', 1, 70000.00, '2026-08-06'),
(108, 5, 'Mouse', 2, 900.00, '2026-08-07')
ON CONFLICT (order_id) DO NOTHING;
```
### WITH

- Uses a CTE (`customer_sales`) to calculate total spending for each customer.
- Joins the CTE with `customers` and ranks customers by total spend.

```sql
WITH customer_sales AS 
(
    SELECT
        customer_id,
        SUM(quantity * unit_price) AS total_spend
    FROM orders
    GROUP BY customer_id
)
SELECT
    c.customer_name,
    cs.total_spend
FROM customers c
JOIN customer_sales cs ON c.customer_id = cs.customer_id
ORDER BY cs.total_spend DESC;
```

### USE Function  ROW_NUMBER

- Uses the `ROW_NUMBER()` window function to assign a sequential number to each order.
```
-- `ROW_NUMBER()` assigns a sequential number to each row.
-- `OVER (ORDER BY unit_price DESC)` defines the order of numbering, from the highest to the lowest 

unit price.
ROW_NUMBER() OVER (
    ORDER BY unit_price DESC
) AS row_number

```

- Orders are ranked from the highest to the lowest `unit_price`.

```sql
SELECT
    order_id,
    product,
    unit_price,
    ROW_NUMBER() OVER (
        ORDER BY unit_price DESC
    ) AS row_number
FROM orders;
```
### RANK() Window Function (quantity * unit_price)

- `RANK()` assigns a rank to each row based on the specified ordering.
- `quantity * unit_price AS revenue` calculates the revenue for each order.
- `OVER (ORDER BY quantity * unit_price DESC)` ranks orders from the highest to the lowest revenue.
- If two orders have the same revenue, they receive the same rank, and the next rank is skipped.

```sql
SELECT
    customer_id,
    quantity * unit_price AS revenue,
    RANK() OVER (
        ORDER BY quantity * unit_price DESC
    ) AS revenue_rank
FROM orders;
```
### DENSE_RANK() Window Function

- `DENSE_RANK()` assigns a rank to each row based on the specified ordering.
- `quantity * unit_price AS revenue` calculates the revenue for each order.
- `OVER (ORDER BY quantity * unit_price DESC)` ranks orders from the highest to the lowest revenue.
- If two orders have the same revenue, they receive the same rank.
- Unlike `RANK()`, `DENSE_RANK()` does not skip the next rank.

```sql
SELECT
    customer_id,
    quantity * unit_price AS revenue,
    DENSE_RANK() OVER (
        ORDER BY quantity * unit_price DESC
    ) AS dense_rank
FROM orders;
```
```text
RANK()        → 1, 2, 2, 4
DENSE_RANK()  → 1, 2, 2, 3

```
### ROW_NUMBER() vs RANK() vs DENSE_RANK()

Example with duplicate revenue values:

| Revenue | ROW_NUMBER() | RANK() | DENSE_RANK() |
|--------:|-------------:|-------:|-------------:|
| 100     | 1            | 1      | 1            |
| 90      | 2            | 2      | 2            |
| 90      | 3            | 2      | 2            |
| 80      | 4            | 4      | 3            |

- `ROW_NUMBER()` — assigns a unique sequential number to every row.
- `RANK()` — gives equal values the same rank and skips the next rank.
- `DENSE_RANK()` — gives equal values the same rank but does not skip ranks.

```text
ROW_NUMBER() → 1, 2, 3, 4
RANK()       → 1, 2, 2, 4
DENSE_RANK() → 1, 2, 2, 3
```

### Running Total with Window Function (cumulative revenue, showing the total revenue accumulated)

- `quantity * unit_price AS revenue` calculates the revenue for each order.
- `SUM(quantity * unit_price) OVER (...)` calculates a cumulative running total without grouping rows.
- `ORDER BY order_date, order_id` defines the sequence in which orders are accumulated.
- `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` means: start from the first row and include all rows up to the current row.
- `running_total` therefore grows after each order.
```text
Order   Revenue   running_total
101     100       100
102      50       150
103     200       350
104      80       430

100
100 + 50 = 150
150 + 200 = 350
350 + 80 = 430

`running_total` — cumulative revenue: the current order revenue plus the revenue from all previous orders.

running_total = вся выручка по всем предыдущим заказам + выручка текущего заказа
```

```sql
SELECT
    order_date,
    order_id,
    quantity * unit_price AS revenue,
    SUM(quantity * unit_price)
    OVER (
        ORDER BY order_date, order_id
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS running_total
FROM orders;
```
```text
Example:

| Order | Revenue | Running Total |
|------:|--------:|--------------:|
| 101 | 100 | 100 |
| 102 | 50 | 150 |
| 103 | 200 | 350 |
| 104 | 80 | 430 |
```
```text
UNBOUNDED PRECEDING → from the first row
CURRENT ROW         → up to the current row
running_total       → accumulated sum
```

### Product Total with PARTITION BY (same Product)

- `quantity * unit_price AS revenue` — calculates the revenue for each individual order.
- `SUM(quantity * unit_price) OVER (PARTITION BY product)` — calculates the total revenue for all orders of the same product.
- `PARTITION BY product` — divides the result into groups by product without collapsing the rows.
- `product_total` — shows the total revenue generated by that product across all its orders.

```sql
SELECT
    product,
    customer_id,
    quantity * unit_price AS revenue,
    SUM(quantity * unit_price)
    OVER (
        PARTITION BY product
    ) AS product_total
FROM orders;
```

```sql
SELECT
    product,
    SUM(quantity) AS total_quantity,
    SUM(quantity * unit_price) AS total_sales
FROM orders
GROUP BY product;

```

Example:

| Product | Revenue | Product Total |
|---------|--------:|--------------:|
| Laptop  |   75000 |        145000 |
| Laptop  |   70000 |        145000 |
| Mouse   |    1600 |          3400 |
| Mouse   |    1800 |          3400 |

- `revenue` — revenue of the current order.
- `product_total` — total revenue from all orders for the same product.


### Top Order per Product with CTE and ROW_NUMBER()

- `WITH ranked_orders AS (...)` — creates a CTE with ranked orders.
- `PARTITION BY product` — creates a separate ranking for each product.
- `ORDER BY quantity * unit_price DESC` — ranks orders from highest to lowest revenue within each product.
- `ROW_NUMBER()` — assigns `1, 2, 3...` inside each product group.
- `WHERE rn = 1` — keeps only the highest-revenue order for each product.

```sql
WITH ranked_orders AS (
    SELECT
        product,
        order_id,
        quantity * unit_price AS revenue,
        ROW_NUMBER() OVER (
            PARTITION BY product
            ORDER BY quantity * unit_price DESC
        ) AS rn
    FROM orders
)
SELECT
    product,
    order_id,
    revenue
FROM ranked_orders
WHERE rn = 1;
```

Example:

| Product  | Order ID | Revenue |
|----------|---------:|--------:|
| Laptop   |      101 |   75000 |
| Keyboard |      106 |    1600 |
| Monitor  |      104 |   36000 |
| Mouse    |      102 |    1600 |
| Webcam   |      105 |    7500 |

- `rn = 1` — the top-performing order within each product group.
